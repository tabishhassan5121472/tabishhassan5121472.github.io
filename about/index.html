How the blog tests things

Most articles start from a claim people are sharing, for example "this setting makes coding agents cheaper". I try it myself and report what happened.

  • Same setup for every option. Same machine, same model, same task, and several runs each where it matters.
  • Rules written before the results. If I score something, the checklist is fixed before I look at the output.
  • Limits stated. Each test says what it did not cover: other models, other machines, small samples.
  • Sources linked. The original post or document is credited and linked.
  • AI help is disclosed. I use AI coding agents to build test harnesses and drafts. Results come from the actual runs, and I check the numbers before publishing.
  • Corrections. If you find a mistake, email me and I'll fix it and note the update date on the article.
